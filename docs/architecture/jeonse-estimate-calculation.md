# 전세 예상 금액·금리 계산 계약

## 이번 수정

금액 산정과 금리 확인을 분리한다. `amount` 기준으로 금액을 계산할 수 있다면 금리 스펙 또는 금리 팩트가 없어도 `estimatedLoanAmount`, `ownFundsRequired`는 제공한다. 금리 범위가 불완전하거나 음수·역전이면 `rateMin`, `rateMax`, `monthlyInterestMin`, `monthlyInterestMax`는 모두 null이다. 0%나 예시 금리로 대체하지 않는다.

추천 보증금 상한은 확인된 수치 제약의 교집합이다.

```text
대출 예상액 = min(희망보증금 × 대출비율, 상품 대출한도)
필요 자기자금 = 희망보증금 - 대출 예상액
추천 보증금 = min(사용 가능 현금 + 상품 대출한도,
                  사용 가능 현금 ÷ (1 - 대출비율),
                  조건식의 DEPOSIT_CAP 상한)
```

대출 비율은 팩트의 백분율(예: 80)을 사용한다. 추천 보증금과 대출 예상액은 원 미만 버림, 월이자는 기존 원 단위 반올림을 유지한다. 100% 비율은 자기자금 비율 제한을 적용하지 않는다. 현금이 없거나 참조된 보증금 상한을 확인할 수 없으면 추천 보증금은 null이다. 명시적인 현금 0원은 미확인과 다르다.

예를 들어 현금 1천만원, 비율 80%, 대출한도 1억5천만원이면 추천 보증금은 1억6천만원이 아니라 **5천만원**이다. 이는 계산 검증용 가정이며 특정 상품의 최신 조건을 주장하는 예시가 아니다.

희망보증금 기준 예상 대출액은 자기자금 부족 때문에 줄이거나 없애지 않는다. 추천 가능한 보증금과 사용자가 희망한 보증금의 대출 예상액을 구분하기 위해서다.

## 유지하는 경계

- FAIL, 금액 스펙 없음, 비율·한도 팩트 미확인 시 금액을 만들지 않는다.
- NEED_INFO는 승인이나 매칭 확정으로 바꾸지 않는다.
- 순자산·계좌 잔액을 사용 가능 현금으로 대체하지 않는다.
- 규칙의 DRAFT/ACTIVE 상태와 기존 Flyway 데이터는 변경하지 않는다.
- 은행 보증 심사, 증빙소득 및 기타 입력하지 않은 조건에 따른 실제 한도 차이는 여전히 존재한다. 추천 보증금은 수치상 참고값이지 실제 승인 한도가 아니다.
