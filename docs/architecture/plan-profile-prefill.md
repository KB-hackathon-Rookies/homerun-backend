# 회원정보 → 1루 입력 초깃값

## API 연결

모든 API는 로그인한 사용자만 호출할 수 있다. 기존 닉네임 PATCH API는 변경하지 않는다.

1. `GET /api/v1/members/me/diagnosis-profile`: 현재 생년월일·병역기간 조회.
2. `PUT /api/v1/members/me/diagnosis-profile`: 두 필드의 전체 스냅샷 저장. 예: `{"birthDate":"1998-05-14","militaryMonths":18}`. 생략/null은 초기화이므로 부분 수정 API처럼 사용하지 않는다.
3. `GET /api/v1/plans/{planId}/input/profile-prefill`: 소유한 계획의 생년월일·병역기간 초깃값과 출처 조회. 저장된 plan_input이 없어도 조회 가능하다.
4. 사용자가 확인한 뒤 기존 `PUT /api/v1/plans/{planId}/input`에 다른 입력을 포함한 전체 스냅샷을 저장한다. 기존 저장 로직이 이력과 재계산 상태를 관리한다.

조회 API는 회원정보를 계획에 자동 저장하거나 진단을 실행하지 않는다. 회원정보 변경도 기존 계획을 변경하지 않는다. 프론트는 초깃값 응답이 늦게 도착해도 화면에서 사용자가 수정한 값을 덮어쓰면 안 된다.

## 필드별 우선순위

| 상태 | value | source |
| --- | --- | --- |
| 해당 필드를 명시적으로 모름 선택 | null | EXPLICIT_UNKNOWN |
| 계획에 저장한 값 있음 (0 포함) | 저장값 | SAVED_INPUT |
| 빈 필드이고 회원정보 있음 | 회원정보 값 | MEMBER_PROFILE |
| 두 곳 모두 미입력 | null | UNAVAILABLE |

`EXPLICIT_UNKNOWN`은 그대로 `unknownFields`를 유지한다. 프로필 값이 생겼다는 이유만으로 모름을 지우지 않는다. `source`는 이번 제안의 출처이며 은행/기관이 검증했다는 뜻이 아니다. 계획 저장 후에는 SAVED_INPUT으로 보이고, 회원정보 원본 출처를 영구 추적하는 기능은 이번 범위가 아니다.

## 병역기간과 호환성

- 기존 app_user.military_months 기본값은 0이라 미입력과 실제 미복무를 구분할 수 없었다.
- V30은 `military_months_confirmed=false`를 추가한다. 기존 숫자는 보존하되 명시적 재입력 전에는 조회값을 null로 반환한다.
- 새 PUT에서 0~60 입력 시 사용자 확인 상태가 된다. null은 확인 상태를 해제한다. 0은 명시적 미복무이고 null은 미확인이다.
- 생년월일은 과거 날짜만 허용한다. 프로필을 저장했다고 특정 정책의 병역 연령 보정이 자동으로 인정되는 것은 아니다.

## 후속 범위

오픈뱅킹 조회값의 진단 입력 연계, 수동 수정 출처 추적, 금융 확인 상태 검증은 아직 남아 있다. 계좌 자산을 순자산/가용현금으로 대체하거나 실수령 추정액을 은행 증빙 소득으로 확정하지 않는다. 혼인 특례·RIR·알림은 추가하지 않는다.
