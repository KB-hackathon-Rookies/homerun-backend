# 데모 페르소나

시연에서 쓰는 가짜 금융 프로필이다. **한 페르소나 = 한 사람의 재무 이야기**이고, 오픈뱅킹 화면(계좌·잔액·거래내역·대출)과 진단 입력(소득·순자산)이 같은 숫자를 말한다.

숫자의 출처는 `Persona`(`domain/openbanking/type/Persona.java`) 하나다. 계좌를 어떻게 쪼개 담을지만 `MockPersonaFixtures`(`global/external/openbanking/`)가 정하고, 합이 페르소나 값과 맞는지는 `MockDataOpenBankingClientTest` 가 페르소나마다 검사한다. 그러니 **숫자를 고칠 일이 있으면 `Persona` 를 고친다.**

전부 `external-api.open-banking.mock-data=true`(env `OPEN_BANKING_MOCK_DATA`)일 때만 존재한다. 기본값은 false 이고, 꺼져 있으면 아래 경로는 404 이며 조회는 실제 금융결제원으로 나간다.

## 시연 기본 — 김첫집 (`KIM_FIRST`)

없다. **대출 목록이 비어서 내려온다** — 잔액 0원짜리 대출 행이 아니다.

### 보여 주는 판정

청년 버팀목 전세대출과 반환보증이 **다 되는 기준선**이다. 연 소득은 3,000만원(월 250만 × 12)으로 청년 버팀목 소득기준 5,000만원 안이고, 대출이 없어 부채 쪽에서도 걸리지 않는다. 시연 대본의 밝은 기본 경로다.

## 시연에서 부르는 순서

두 경로 모두 로그인 토큰이 필요하고, `mock-data` 플래그가 켜져 있어야 한다.

### 1. 가짜 오픈뱅킹 연결 (인가 팝업 없이)

```bash
curl -X POST 'http://localhost:8080/api/v1/open-banking/mock-connect' \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

여기까지만 하면 계좌·잔액·거래내역·요약이 **김첫집**으로 답한다.

### 2. 페르소나 싣기 (진단 입력까지 확정 상태로)

```bash
curl -X POST 'http://localhost:8080/api/v1/plans/{planId}/input/open-banking-sync/mock' \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"persona":"KIM_FIRST"}'
```

`persona` 는 `KIM_FIRST` · `LEE_TIGHT` · `PARK_SENIOR` 셋 중 하나다. 이 호출 이후로는 그 회원의 오픈뱅킹 조회도 실은 페르소나를 따라간다 — 즉 계좌 화면과 진단 입력이 계속 같은 사람을 말한다. 페르소나는 회원별로 마지막에 실은 것이 남고, 서버를 재시작하면 다시 김첫집으로 돌아간다.

### 3. 다른 페르소나로 갈아타기

같은 호출을 `persona` 만 바꿔 다시 하면 된다. 별도의 초기화 호출은 없다.
